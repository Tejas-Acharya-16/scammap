## In the browser

- qrcodejs 1.0.0, loaded from cdnjs, draws the QR code on the judge console (`/judge`). The page works without it.
- Leaflet 1.9.4 (BSD-2-Clause), loaded from cdnjs, draws the live scam map (`/live`). Map tiles come from the OpenStreetMap Foundation's tile server (tile.openstreetmap.org, no API key; used under its tile usage policy), with OpenStreetMap data (© OpenStreetMap contributors, ODbL), and are credited on the map. The viewer's browser fetches the tiles; no report data is sent to them. Without them the page falls back to a plain plot of area centres.
- tweetnacl 1.0.3 (public domain, Unlicense), loaded from cdnjs with a pinned integrity hash, checks signed answers in the "Verify an answer" panel on `/judge`. Without it the panel says NOT CHECKED, and `tools/verify_attestation.py` does the same check. A byte-identical copy is in `tests/e2e/assets` so the browser tests run without a network.
- No web fonts: the pages use the device's system fonts (Inter where the device already has it). All five pages (`/`, `/live`, `/judge`, `/arena`, `/shield`) share one stylesheet, `app/static/theme.css`, written for this project.
- The map pin in the header is drawn in CSS. No logo, image or asset from any other site or company is used.
- Icons are Unicode emoji, drawn by the device's own emoji font. No icon pack and no third-party logos.
- The "Ask family before you pay" button on a Check result is a WhatsApp click-to-chat link (`https://wa.me/?text=...`) with a ready message. WhatsApp opens only when the person taps it, nothing is sent unless they send it, and the server never contacts WhatsApp.

## Data

- No real personal data anywhere. All test and demo data is synthetic: numbers in `+91 90000 xxxxx`,
  made-up UPI IDs, `.example` links, reporter IDs such as `r_demo_N`, networks in `10.x.y`.
- The reference tables in `app/data` (areas, the verified list, scam types, channels) come from the data
  tables in the organisers' brief and are used as data files, as the event rules allow. The shops in the
  verified list are the organisers' made-up test businesses.
- The message reader's training data, `tools/ai/messages.jsonl` (591 messages), and its 10 held-out test messages
  (`tests/unit/data/ai_heldout.jsonl`) were written by Claude Code during the event. They are synthetic: `+91 90000`
  numbers, `.example` links, made-up UPI IDs, banks and shops. No real message and no third-party dataset.
  The model is trained by our own code (`tools/ai/train_reader.py`, standard library only). No pre-trained model,
  and no library in the browser: `app/static/ai/reader.js` is written for this project.
- The AI Call Shield's training lines, `tools/ai/shield_lines.jsonl` (740 lines, generated by `tools/ai/shield_data.py`
  from templates), its 12 held-out calls (`tests/unit/data/shield_heldout.jsonl`) and the demo calls on `/shield` were
  written by Claude Code during the event. They are synthetic: no real call, no real person, no third-party dataset.

## AI tools

They helped us write code, tests and documents. None of them runs inside the product: every verdict comes
from deterministic code, and no outside model is called while the server answers a request.

The product has three small models of its own, both written and trained during the event on synthetic data
only, and both advisory: neither sets, raises or lowers a verdict, and neither is an LLM.

- The **AI watchdog** (`app/engine/watchdog.py`, on the server): a logistic regression with 15 weights
  (`app/data/watchdog_model.json`), trained with `tools/train_watchdog.py` on our own attack simulator, with
  the Python standard library. It adds an opinion on whether a number's reports look coordinated.
- The **on-device message reader** (see Data): it runs in the browser and only suggests a kind of scam.
- The **AI Call Shield** (`app/static/ai/shield.js`, in the browser): Naive Bayes over each line a caller says, plus a
  hidden Markov model over the steps of 4 scam scripts. Trained with `tools/ai/train_shield.py` (standard library only)
  on synthetic lines. It suggests which script and step a call is at and what usually comes next; it sends nothing.
